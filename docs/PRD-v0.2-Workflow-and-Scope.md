# 原点 PRD v0.3：老板资料驱动的短视频创作流水线

版本：v0.3（保留原文件路径，避免破坏已有引用）
日期：2026-08-19
状态：产品范围基线；本轮 renderer 为交互垂直切片，真实生成与渲染能力以测试和实现为准

## 1. 产品判断

### 1.1 第一用户

第一用户不是专业创作者，而是需要亲自做内容获客的老板、个体户、门店主理人和小微企业主。他们通常懂自己的生意，也有手机实拍素材，但不熟悉选题、脚本、分镜、素材检索和剪辑术语。

### 1.2 产品定位

原点是本地优先的短视频创作工作台：先把老板本人、经营业务、目标客户、可公开事实和实拍素材沉淀为经确认的资料，再把一次视频意图转成可编辑脚本、逐镜素材方案和可审阅的拼合提案。

一句话：

> 先认识你和你的生意，再把你已经有的真实素材，变成一条能讲清楚、能补齐、能拼起来的视频。

差异不在“多生成几篇文案”，而在每一段脚本和每一个镜头都能回答：用了哪条老板资料、匹配了哪段真实素材、哪里仍缺素材、哪里是 AI 生成，以及用户下一步能做什么。

### 1.3 不做的事情

- 不要求老板先学会 `ThoughtPlan`、时间线或内部数据结构；复杂推理留在后台，用户只确认事实、结构和结果。
- 不把一张几十项的长表作为首次使用门槛。
- 不根据年龄、性别、地域或口音套用人物刻板印象。
- 不擅自补写个人经历、资历、销量、客户效果、医疗效果、收益承诺或荣誉。
- 不将“生成缺失镜头”理解为绕过报价、授权和审阅的黑盒成片。
- 不自动发布，不删除原素材，不覆盖旧脚本或旧成片版本。
- 不与剪映竞争完整的模板、花字、音效和素材生态。

## 2. 首条完整工作流

第一条必须跑通的闭环改为：

```text
建立老板资料 + 上传本人/门店/产品/过程实拍素材
  → 选择固定模板，或描述想做的视频
  → AI 推荐结构并用已确认资料填充脚本
  → 用户审阅、编辑、锁定，或“一键换一版”
  → 从已确认脚本生成分镜
  → 优先匹配用户实拍素材及可用时间段
  → 汇总未覆盖分镜
  → 一次确认后批量生成允许生成的缺失素材
  → 按播放顺序审阅每个分镜对应的视频
  → 冻结脚本与素材清单
  → 一键创建拼合提案
  → 预览、逐镜替换、重新拼合、导出
```

研究、对标、热点和平台数据回流仍属于产品内核，但不阻断这条“资料 → 脚本 → 素材 → 拼合”闭环。

## 3. 用户任务与验收

### 任务 A：建立老板资料与本人素材库

用户填写希望如何称呼、出镜身份、行业、经营内容、目标客户、差异化、表达方式和内容边界，并上传本人、门店、产品、服务过程等实拍视频。

系统先收最小资料，再根据用户选择的脚本模板动态追问 2–5 项。系统生成“我对你和生意的理解”，明确区分用户确认事实、素材观察结果和 AI 推断，用户确认后形成版本化资料。

验收：

- 用户能在 5 分钟内完成最小可用资料；
- 每个问题说明“这会用于哪一段脚本或哪类分镜”；
- 不要求实名、精确生日、身份证、家庭住址、收入或健康信息；
- 素材逐条记录权属、出镜人授权、允许用途及是否允许衍生生成；
- 用户可更正、删除、撤回授权；资料更新不会静默改写历史脚本。

### 任务 B：决定这条视频做什么

系统提供两个并行入口：

1. 从固定模板选择“老板自我介绍、客户痛点、知识避坑、真实案例、幕后过程”；
2. 用一句话描述想做的视频，由 AI 推荐一个最合适的结构，用户可改选。

验收：用户无需理解脚本术语，也能在 1 分钟内确定视频目标、主要受众、模板、平台和目标时长。

### 任务 C：生成并选择脚本

AI 用经确认的资料、所选模板和本条视频意图填充结构。用户可以编辑任一段、锁定不希望变化的段落，也可以“一键换一版”。

验收：

- 每个个性化事实都能回指资料或证据；
- 缺少依据的内容显示“待确认”，不得写成确定事实；
- 换一版创建并列版本，旧版可比较、恢复，不覆盖用户修改；
- 脚本版本固定引用 `profileRevision + templateVersion + briefRevision`；
- 只有用户确认的脚本版本才能进入正式分镜。

### 任务 D：生成分镜并匹配实拍素材

系统把已确认脚本拆成分镜，为每镜给出台词、画面目的、建议时长和来源策略，并优先从用户上传的实拍视频中匹配可用时间段。

验收：

- 每镜显示台词、画面目的、目标时长、候选素材、匹配理由和权属状态；
- 低置信候选只作为建议，不静默自动选中；
- 用户可预览、替换、清空或上传新素材；
- 修改脚本后，受影响的分镜和素材映射标记为已过期。

### 任务 E：批量处理缺失分镜

系统把未覆盖分镜分为四类：

- 可用图片/视频模型生成；
- 应由老板补拍；
- 可用字幕、图形或静态产品图替代；
- 因真实证据、肖像、声音、品牌或行业风险被阻断。

“一键生成”表示用户一次确认范围、报价和授权后批量提交所有可生成项，不表示系统可以跳过确认。

验收：

- 生成前展示分镜数量、生成方式、预计费用、预计时间和可能收费的失败规则；
- 只提交用户确认且允许生成的镜头；
- 单镜失败不影响已成功结果，可单独重试、换模型或改为补拍；
- 生成产物进入素材库，保留 Provider、模型、参数摘要、内容编号和 AI 标识状态。

### 任务 F：审阅分镜视频清单

系统按最终播放顺序罗列每个分镜对应的视频。用户可逐镜预览、替换、重新生成、调整时长，或跳过明确标为可选的镜头。

验收：所有必需分镜都有选中素材，且权属和授权可用后，项目才进入“可以拼合”状态。

### 任务 G：一键拼合

系统根据冻结的脚本版本、分镜版本和素材清单创建确定性拼合提案，执行基础裁切、时长适配、音量处理、字幕和有限转场。

验收：

- 拼合生成新版本，不覆盖旧成片；
- 用户能看到最终清单和来源后再确认执行；
- 单镜替换后可重新拼合，无需重做未受影响步骤；
- 失败保留恢复点，不自动发布；
- 输出 MP4、SRT/VTT、RenderManifest 和通用媒体交付包。

## 4. 老板资料设计

### 4.1 采集原则

采用三层设计：

1. **最小必填核心资料**：足够生成不空泛的第一版脚本；
2. **按模板动态追问**：仅询问当前视频类型真正需要的信息；
3. **素材与授权**：AI 自动提取技术和内容标签，用户只确认权属、授权和用途。

支持自然语言填写后由 AI 抽取结构化字段，再让用户确认；不知道的事实允许为空。

### 4.2 首屏 9 个核心问题

1. 大家怎么称呼你？
2. 你是做什么行业、什么生意的？
3. 你主要卖什么或提供什么服务？
4. 你最想服务哪类人？
5. 他们最头疼什么、最想得到什么？
6. 客户为什么选择你？
7. 你希望观众觉得你是个怎样的人？
8. 这阶段最想实现什么目标？
9. 有哪些话题、承诺或人物绝对不能出现？

### 4.3 字段分组

| 分组 | 最小必填 | 渐进/条件字段 | 对脚本和画面的作用 |
|---|---|---|---|
| 对外人物身份 | 对外称呼、出镜身份、行业 | 年龄段、城市/服务区域、方言 | 开场称呼、人物记忆点、地方化表达 |
| 人设与表达 | 3 个性格词、希望被看作哪类人、表达风格 | 语速、方言比例、幽默尺度、常用表达、参考账号 | 句长、语气、情绪和长期一致性 |
| 从业经历与可信事实 | 擅长领域 | 从业年限区间、入行原因、转折、资质、奖项、可公开案例及证据 | 可信理由、故事冲突、证据段 |
| 生意基本信息 | 公开品牌/门店名、经营形态、主营产品或服务、服务地区 | 经营年限、门店规模、团队角色 | 场景、人物关系、行业术语 |
| 产品/服务 | 优先推广项、解决的问题、核心卖点 | 价格区间、优惠有效期、交付流程、适用与不适用人群、售后 | 产品主体、演示镜头、CTA |
| 差异化与证据 | 客户为什么选你 | 工艺、服务细节、评价、前后对比、复购原因、常见误解 | 钩子、论证、反转、证明镜头 |
| 目标观众 | 首要客群、主要痛点、想要结果、最大顾虑 | 年龄段、职业/生活阶段、真实提问和常用说法 | 对谁说、前三秒钩子、异议处理 |
| 内容目标 | 目标平台、涨粉/信任/咨询/到店/成交、希望动作 | 账号阶段、更新频率、承接方式 | 信息密度、卖点顺序、结尾行动 |
| 内容边界 | 禁止话题、禁用承诺、不能展示的人/地点/物品 | 行业声明、是否允许价格/竞品/家人 | 防止 AI 越界和违规 |

年龄只收年龄段，对外称呼不等于实名；性别、家庭状况、收入、健康、精确位置均不作为默认必填。

### 4.4 实拍素材与授权字段

建议首次引导上传：1 段 20–60 秒正面自我介绍，以及门头、工作环境、制作过程、核心产品、服务过程等 5–10 段素材；这只是建议，不阻断脚本生成。

AI 自动提取并由用户确认：

- 人物、物品、地点、动作；
- 景别、横竖屏、时长、画质、是否有对白；
- 可用时间段、转写、OCR 和内容标签。

用户必须确认：

- 是否本人拍摄、素材权利归属、是否允许商用；
- 画面人物的肖像和声音授权；
- 允许的平台、项目和授权期限；
- 是否含未成年人、客户隐私或敏感经营信息；
- 是否允许据此生成相似产品、场景、人物形象或声音。

形象和声音生成必须单独授权；第三方授权不完整时支持排除、静音或模糊处理。

## 5. 脚本模板系统

固定模板不是固定文案，而是版本化、可校验的槽位结构。P0 提供五类：

| 模板 | 核心结构 | 额外动态追问 |
|---|---|---|
| 老板/品牌自我介绍 | 身份钩子 → 为什么入行 → 做什么 → 与别人不同 → 邀请了解 | 入行原因、转折、价值观 |
| 客户痛点—解决方案 | 痛点场景 → 常见误区 → 解决方法 → 产品/服务证明 → CTA | 顾虑、购买触发、适用边界 |
| 知识干货/避坑 | 问题钩子 → 专业身份 → 3 个步骤/误区 → 边界提示 → 关注/咨询 | 资质、证据、风险提示 |
| 真实案例/前后变化 | 客户背景 → 冲突 → 过程 → 结果与证据 → 可复制启示 | 客户授权、数据出处、有效期 |
| 门店/产品幕后过程 | 同城/产品钩子 → 环境/原料 → 过程 → 细节优势 → 到店/下单 | POI、营业时间、招牌项、优惠有效期 |

通用槽位：

```text
Hook
  → 出镜身份 / 可信理由
  → 客户场景或痛点
  → 核心观点 / 解决办法
  → 演示、案例或证据
  → 适用边界
  → CTA
```

`NarrativeTemplate` 至少保存 `id / version / bestFor / requiredProfileFields / slots / sourcePolicy / durationRules / shotHints / allowedMaterialTypes`。每个已填充槽位保存 `sourceFactIds`、确认状态和风险提示。

自定义意图入口也必须先映射到一个结构，用户确认后再填充，避免自由文本直接进入黑盒长文。

## 6. 分镜、素材匹配与生成

### 6.1 单镜素材状态

```text
unmatched
  → candidates_found
  → selected_existing

unmatched
  → generation_required
  → generating
  → generated_review
  → selected_generated

unmatched
  → shoot_required / graphic_fallback / blocked / skipped
```

用户界面使用易懂中文：`待匹配 / 有候选 / 已用实拍 / 待生成 / 生成中 / 已用生成素材 / 需补拍 / 被阻断`。

### 6.2 匹配顺序

匹配依次考虑：

1. 权属和授权是否允许；
2. 分镜需要的人物、产品、地点和动作；
3. 可用时间区间、画幅、景别、时长和技术质量；
4. 台词语义、转写、OCR 和素材标签；
5. 用户历史采用/拒绝反馈。

结果必须显示匹配理由，不以“AI 认为合适”代替证据。

### 6.3 生成边界

优先级为：已有视频 → 真实产品静态图/图形 → 图生视频 → 文生视频。必须由真实证据承担的镜头、未经授权的真人形象/声音、虚假客户见证和可能误导消费者的效果镜头不得自动生成。

## 7. 核心对象与状态

### 7.1 核心对象

- `CreatorIdentityProfile`：称呼、身份、年龄段、地域、出镜设定；
- `BusinessProfile`：行业、经营方式、产品服务、差异化和资质；
- `AudienceProfile`：客户、场景、痛点、目标、异议和触发点；
- `VoiceProfile`：语言、表达节奏和边界；
- `ProfileFact`：事实值、来源、敏感级别、确认状态和允许用途；
- `ClaimEvidence`：资质、案例、数字和宣传主张的证据；
- `ProfileAsset / AssetSegment / AssetRights`：实拍素材、可用区间和授权；
- `CreationBrief`：本条视频的目标、描述、平台和时长；
- `NarrativeTemplate`：固定模板及版本；
- `ScriptVariantGroup / ScriptVariant`：脚本换版、比较和恢复；
- `Storyboard / MaterialAssignment`：分镜及实拍/生成素材映射；
- `GenerationBatch / CostLedger`：批量生成状态和费用；
- `AssemblyManifest / VideoDraft`：冻结拼合输入和结果版本。

### 7.2 资料状态

```text
draft → minimally_ready → ai_summarized → confirmed → stale → archived
```

### 7.3 项目状态

```text
brief_draft
  → script_generating → script_review → script_approved
  → storyboard_building → matching → gap_review
  → gap_generating → coverage_review → ready_to_assemble
  → assembling → video_review → exported
```

关键回路：

- `script_review --换一版--> script_generating`
- `gap_review --上传/补拍--> matching`
- `coverage_review --替换/再生成--> gap_review`
- `video_review --替换分镜--> coverage_review`
- `video_review --重新拼合--> assembling`

## 8. 产品工作区

主导航按真实任务收拢：

1. **创作流水线**：老板资料、选模板/意图、脚本、素材匹配、缺口生成、拼合；
2. **素材库**：本人、门店、产品、过程和生成素材的本地事实库；
3. **研究与选题**：对标、热点、选题机会和参考内容；
4. **发布复盘**：发布物、数据快照、实验对比和记忆建议；
5. **设置**：工作区、Provider、预算、模型和本地分析。

普通老板不需要在主导航中区分“脚本、分镜、AI 剪辑”等内部阶段；阶段应作为同一项目的进度出现。

## 9. 功能范围

### 9.1 P0：首条闭环

- 最小老板资料、事实确认、版本和资料摘要；
- 实拍素材上传、基础分析、标签、权属和授权；
- 五个模板 + 自定义意图到结构推荐；
- 资料驱动脚本、来源追溯、编辑、锁定和换一版；
- 脚本到分镜、素材候选、匹配理由和逐镜选择；
- 缺口分类、生成报价、批量提交、部分失败与单镜重试；
- 分镜视频清单、覆盖闸门、冻结 manifest 和一键拼合；
- MP4、SRT/VTT、RenderManifest 和通用媒体包；
- 隐私、成本、授权、AI 内容标识和恢复状态。

- TikHub 对标账号、作品、热点和指标快照；
- 资料动态追问质量评测与内容支柱；
- FCPXML/OTIO 导出；
- 发布记录、数据快照和复盘建议；
- 更多行业模板、平台差异化版本和可复用镜头偏好；
- 本地 Ollama、Whisper、ComfyUI 等 Provider。

### 9.3 P2：后续探索

- 经单独授权的音色克隆和本人形象生成；
- 数字人和口型同步；
- 多平台自动发布；
- 团队协作、审批和素材权限；
- 复杂花字、模板、转场和自动包装；
- 账号实验自动归因和创作记忆推荐。

## 10. AI、隐私、合规与成本

### 10.1 AI 的权力边界

AI 输出分为建议、结构化计划和确定性执行。AI 不得：

- 把推断伪装成老板确认事实；
- 覆盖用户原资料、脚本、分镜或成片；
- 删除原素材；
- 绕过报价、预算、授权和任务状态调用付费 Provider；
- 在冻结后的渲染热路径重新选择素材或改写脚本；
- 把未经证实的账号数据、客户评价或个人经历写入长期记忆。

### 10.2 隐私

- 默认本地保存和分析；云端调用前展示将上传哪些文字、图片或视频；
- 只采集实现当前创作目的所需的最小范围；
- 年龄使用区间，位置默认使用城市/服务区域，EXIF 精确位置不进入脚本和导出；
- 敏感个人信息和本人形象/声音衍生生成单独授权；
- 原片、代理、缩略图、索引和生成使用记录可追溯、可联动删除；
- 提供导出、更正、删除和撤回授权。

### 10.3 AIGC 标识

每个生成分镜保存 Provider、模型、参数摘要、内容编号和标识状态。导出不得丢失 AI 元数据，并在发布前提示显式标识要求。真实接入需符合 2025 年 9 月 1 日施行的《人工智能生成合成内容标识办法》。

### 10.4 成本

- 素材检索优先，生成兜底；
- 一键生成是“一次确认后批量提交”，不是免确认；
- 展示逐镜报价、总价、预计耗时、失败/取消计费规则和 Provider 差异；
- 支持单次、每日或月度预算上限；
- 低清预览优先，选中后再生成高质量版本；
- 按 `storyboardRevision + prompt + parameters` 去重，防止重复点击收费；
- 本地拼合不触发额外云调用。

## 11. 成功指标

所有指标必须绑定时间窗口、样本量和数据来源：

- 最小资料完成率、完成时长和动态追问放弃率；
- 第一版脚本中“有来源事实”的覆盖率；
- 换一版后采用率及用户改写比例；
- 分镜中实拍素材覆盖率、低置信匹配被替换率；
- 缺失分镜中生成/补拍/图形替代的比例；
- 批量生成一次成功率、单镜重试率和单位成片生成成本；
- 从创建意图到第一版拼合提案的时间；
- AI 建议采用/拒绝原因；
- 拼合与导出成功率、本地项目恢复和素材重定位成功率。

## 12. 主要风险与对策

| 风险 | 后果 | 处理方式 |
|---|---|---|
| 首次建档过长 | 老板在获得价值前离开 | 9 个核心问题 + 模板动态追问 + 允许稍后补充 |
| 资料不完整或矛盾 | 脚本空泛或错写事实 | 显示缺口和冲突；未知保留为空；用户确认后才引用 |
| 一键换版覆盖修改 | 用户不再信任系统 | 并列版本、锁定段落、可比较和恢复 |
| 素材误匹配 | 画面不相关或权属风险 | 先校验授权；显示理由；低置信不自动选择 |
| 把真实证据误判为可生成 | 误导消费者 | 分镜来源策略 + 风险阻断 + 人工确认 |
| Provider 部分失败 | 整批结果不可用或重复收费 | 单镜任务、幂等键、恢复点、部分成功和单镜重试 |
| 脚本修改后沿用旧素材 | 台词与画面错位 | 下游标记 stale，重新评估受影响分镜 |
| 拼合前仍有空镜头 | 成片有空帧 | 所有必需镜头就绪才开放拼合 |
| UI 看似上线但后端未实现 | 错误预期 | 演示能力明确标识；实现状态以测试和 Provider 合同为准 |

## 13. 当前实现边界

现有项目已经具备结构化脚本和分镜 schema、素材分析/候选召回、`EditProposal → FrozenEditSpec → FFmpeg render` 的基础。当前缺口包括老板资料的 SQLite 事实表、模板/脚本版本组、资料驱动 prompt、生成 Provider 的 submit/poll/download/validate 合同，以及统一的逐镜素材清单。

本轮 renderer 垂直切片用于验证信息架构、状态机和用户路径；其中本地示例脚本、示例匹配、缺失镜头生成和拼合提案不得被描述为真实云端生成或正式渲染。
